# 配置工具技术实现

工具用 Python 标准库实现，GUI 使用 tkinter + ttk。它读取 CSV、执行规则校验，再输出 Unity 使用的 JSON。GUI 默认中文，可切换英文；CLI 保留英文输出。无需安装 AI SDK。

## 数据流程与模块

```text
CSV → SourceTable（原始字符串）→ Rule Engine → 无 ERROR → ContentModel → Unity JSON
```

| 文件 | 职责 |
| --- | --- |
| `Tools/config_tool.py` | CLI 参数与命令分发 |
| `Tools/pipeline_model.py` | 原始表、结构化问题、现有 Unity 数据模型及类型转换 |
| `Tools/pipeline_core.py` | 解析、校验、生成、批量更新及原子写入 |
| `Tools/rule_engine.py` | 检查规则配置，执行各类规则 |
| `Tools/rule_authoring.py` | 草稿、提案检查、OpenAI / DeepSeek / Fake Provider |
| `Tools/ai_credentials.py` | 本次密钥状态、Windows 凭据读写与移除 |
| `Tools/config_gui.py` | 窗口、规则表单与交互 |
| `Tools/gui_i18n.py` | 中文显示与语言切换，保留数据中的原始标识 |
| `Tools/config_desktop.py` | EXE 启动、查找项目、目录选择和启动错误提示 |
| `Tools/build_exe.py` | 在隔离环境中构建 Windows 单文件 EXE |

CLI、GUI 和 Batch 直接调用同一套 `Pipeline` 服务。GUI 展示 `ValidationIssue` 的级别、规则 ID、表、行、字段和说明，不调用 CLI 子进程。语言切换只更新显示，不更改草稿、输入或校验结论；系统底层错误可保留原文细节。

输入位于 `ConfigSource`：`items.csv`、`objectives.csv`、`interactables.csv`。输出为 `Assets/Data/interactables.json` 和 `objectives.json`；items 用于引用检查，没有独立 JSON 输出。Unity 字段、JSON 根节点和 gameplay 均沿用现有实现。

## 外部规则

`ConfigSource/validation_rules.json` 使用 `version: 1` 与 `rules` 列表。示例：

```json
{
  "id": "interactables.minimum",
  "type": "range",
  "table": "interactables",
  "field": "requiredInteractions",
  "params": {"minimum": 1},
  "level": "ERROR",
  "enabled": true
}
```

`id` 是唯一标识；`table` 和 `field` 指定检查位置；`params` 指定标准；`level` 为 ERROR 或 WARNING；`enabled` 控制是否执行。可另加 `description`。`columns`、`required` 在 `params.fields` 中指定多个字段，单独的 `field` 留空。

| 类型 | 检查内容 |
| --- | --- |
| `columns` / `required` | 必需列 / 必填值 |
| `type` | integer、boolean、string |
| `range` / `enum` | 含边界的数值范围 / 允许值列表 |
| `unique` / `regex` | 唯一值 / 正则表达式完整匹配 |
| `reference` | 值是否存在于目标表的目标字段中 |
| `scene_reference` | 指定场景中指定组件的 configId 引用 |

基线规则规定交互次数至少为 1，超过 10 给出警告；interactionType 为 Pickup 或 Device。它还检查 ID 唯一性、物品引用、Batch 目标和 `VerticalSlice_01.unity` 引用。调整标准只需编辑规则；增加全新的执行类型才需要修改引擎。

规则加载、编辑、应用提案和保存时都会检查结构，拒绝未知类型/字段、重复 ID、无效参数、错误正则及不合法引用。已停用的规则也必须具有合法结构。CSV 破损引号、重复表头和行列数不一致始终报错；Unity 整数范围、布尔转换也有独立保护。内容校验中的 WARNING 不阻止生成，ERROR 阻止生成和应用 Batch；合法的规则配置仍可单独保存。

## 草稿、Batch 与写入

规则编辑保存在内存草稿中。校验、生成和批量更新可直接使用草稿，只有“保存规则”写入规则 JSON。保存前比较磁盘快照，避免覆盖其他程序已修改的规则文件；重新加载会读取磁盘版本。

Batch 读取 `batch_interaction_updates.csv`，按以下顺序执行：

```text
检查更新表 → 在内存副本中修改交互次数 → 校验全部修改后数据及场景引用 → 通过后写 CSV
```

因此次数下限只在 Interactable 规则中维护，Batch 会使用同一标准。预览不写文件；应用只更新 `interactables.csv`，之后需另行生成 JSON。

写入先在目标目录创建临时文件，flush / fsync 后用 `os.replace` 替换。JSON 输出先全部准备，再逐个替换；出现普通 I/O 错误时尝试回滚。多个文件的替换不构成断电级事务，也没有并发编辑锁。

## AI 提案

```text
自然语言 + 表头 + 支持的规则类型 + 当前规则
→ Provider → RulePatch → 结构检查 → GUI 预览
→ 用户应用到草稿 → 本地校验 → 用户决定是否保存
```

RulePatch 支持 `add`、`update`（完整规则）和 `disable`。不支持删除、生成 Python 或执行代码。提案应用前会再次检查，并确认草稿未发生变化。AI 不接收 CSV 数据行，也不判断内容是否通过校验。

| Provider | 接口 | 兼容环境变量 |
| --- | --- | --- |
| OpenAI | `/v1/responses`，JSON 模式 | `OPENAI_API_KEY`；可选 `OPENAI_MODEL` |
| DeepSeek | `/chat/completions`，JSON 模式 | `DEEPSEEK_API_KEY`；可选 `DEEPSEEK_MODEL` |
| Fake | 返回预设提案，供测试和离线演示 | 无 |

DeepSeek 默认模型为 `deepseek-flash`，可在界面覆盖；请求关闭 thinking、限制输出 4096 tokens。空内容、截断、拒绝和非法规则都会被拒绝。两种在线服务共用延迟加载的 stdlib HTTPS 请求，超时为 45 秒；GUI 显式传入的密钥优先，输入为空时才回退到环境变量。网络请求在后台线程执行，结果经队列交给 GUI 主线程，后台线程不操作 Tk 控件。

密钥默认只存在当前进程的输入框和服务状态中。用户明确选择记住并应用设置后，通过 `ctypes` 调用 `CredWriteW`，写入 Windows 当前用户的通用凭据；`CredReadW` 加载，`CredDeleteW` 移除。目标名为 `TD-Pipeline-Demo/AI/OpenAI` 或 `TD-Pipeline-Demo/AI/DeepSeek`，持久化范围为当前用户、当前电脑。没有明文配置文件降级路径；存储不可用时仍可使用本次输入。密钥不会加入 AI 提示、提案或错误详情。实现依据：[Windows 通用凭据](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw)。

接口依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[DeepSeek JSON 输出](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)。模型可用性以服务方为准。

## 验证与边界

运行 `py -m unittest discover -s Tools/tests`。测试在临时项目副本中覆盖规则、失败时保留输出、Unity JSON 格式、Batch、草稿、语言切换和 AI 提案；在线请求使用 mock，GUI 使用实际 Tk 控件。`QA/Fixtures/scale_valid` 用于规模回归。

工具只检查规则指定的场景，不扫描全部场景或 prefab。正则使用 Python `re`，无执行超时。GUI 依赖桌面与 tkinter；在线 AI 调用需有效密钥、网络和模型访问权限。

## Windows 打包

在 Windows 项目目录运行 `py Tools/build_exe.py`。脚本在 `Temp` 下创建独立虚拟环境，安装 PyInstaller 6.22.3，输出 `Builds/ConfigTool/TDConfigTool.exe`。构建需要 Python 和网络；运行 EXE 无需另装 Python 或 tkinter。

EXE 从自身所在目录向上查找项目，找不到时弹出目录选择窗口；也支持 `--root 项目路径`。项目数据不嵌入 EXE，避免保存到单文件解压产生的临时目录。原有 Python CLI 保持不变。构建缓存和 EXE 均位于已被 Git 忽略的目录。
