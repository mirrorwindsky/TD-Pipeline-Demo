# 配置工具使用说明

这个工具可以检查 CSV 配置、生成 Unity 数据、调整检查规则，也可以批量修改交互次数。普通操作无需 AI 账号。

## 1. 打开工具

**Windows EXE：** 双击 `Builds/ConfigTool/TDConfigTool.exe` 即可打开，无需安装 Python。若将 EXE 移到项目文件夹之外，启动时选择包含 `ConfigSource` 和 `Assets` 的项目文件夹。CSV、规则和生成结果仍保存在所选项目中。

**从 Python 源码打开：** 电脑需安装 Python 3.10 或以上版本，并包含 tkinter。打开项目文件夹 `TD-Pipeline-Demo`，在此文件夹打开终端，粘贴并运行：

```text
py Tools/config_tool.py gui
```

窗口默认中文。右上角可切换 **English**，切换会保留当前工作；下次打开仍默认中文。如果提示找不到 `py` 或 tkinter，请让负责环境配置的同事协助安装。

## 2. 检查配置并生成数据

1. 点击 **校验草稿**。
2. 在“校验结果”查看错误或警告。行号从表头之后的第 2 行开始；点击一条结果可看完整说明。
3. 用 Excel 等表格软件修改对应 CSV，保存为 UTF-8 CSV，然后重新校验。工具本身不编辑 CSV 内容。
4. 没有错误后，点击 **按草稿生成 JSON**。

**错误会阻止生成；警告允许生成，但需要判断内容是否合理。** 生成后更新的是 `Assets/Data/interactables.json` 和 `objectives.json`，不会自动启动 Unity。

| 位置 | 用途 |
| --- | --- |
| `ConfigSource/items.csv` | 物品 ID 和名称 |
| `ConfigSource/objectives.csv` | 目标 ID、名称和说明 |
| `ConfigSource/interactables.csv` | 交互物配置，如次数、物品需求、提示文字 |
| `ConfigSource/validation_rules.json` | 已保存的检查规则，通过界面编辑即可 |

修改 CSV 时保留原表头和 ID。`interactionType` 当前允许 `Pickup`、`Device`；布尔值填写 `true` 或 `false`。引用不存在的物品或删除场景仍在使用的 ID，会产生错误。

## 3. 调整规则

在 **规则** 页选中一条规则，点击 **编辑**，也可双击该行。表单中带英文括号的类型用于对照规则文件，字段名与 CSV 表头一致。

用交互次数下限练习：

1. 找到 `interactables.minimum`，打开编辑窗口。
2. 将 **最小值** 从 `1` 改为 `4`，点击 **应用到草稿**。
3. 点击 **校验草稿**。当前基线数据会出现 5 条次数不足的错误。
4. 将最小值改回 `1`，再次校验即可通过。

这段操作不必保存。**草稿是本次打开工具后临时调整的规则；“保存规则”才会写入文件。** 若要恢复磁盘上的规则，点击 **重新加载规则**，确认放弃未保存的修改。

规则页还支持 **新增、复制、启用 / 停用、删除**。新增规则时使用不重复的规则 ID，例如 `interactables.id_format`。不知道该选哪种类型时，可按下表判断：

| 想检查什么 | 选择的类型 / 主要填写内容 |
| --- | --- |
| 必须有某些列 / 这些列不能留空 | 必需列 / 必填值；字段列表每行一个 |
| 必须为整数、布尔值或文本 | 数据类型；选择字段与数据类型 |
| 数值不能太小或太大 | 数值范围；最小值、最大值，留空表示该侧不限 |
| 只能填写指定内容 | 允许值；每行填写一个允许值 |
| ID 等值不能重复 | 唯一值；选择字段 |
| 必须符合命名格式 | 命名格式；填写正则表达式，不熟悉时请同事协助 |
| 引用必须存在 | 跨表引用；填写目标数据表和目标字段 |
| 场景中的配置引用必须存在 | 场景引用；通常保留项目现有配置 |

级别选 **错误** 会阻止写入，选 **警告** 仅作提醒。“允许空值”会跳过空值检查；若另有必填规则，该规则仍会生效。ID、路径和字段名请保持拼写准确。

**按草稿生成 JSON、应用批量更新都使用当前草稿，即使它还没保存。** 若希望下次打开工具或运行命令行时使用相同规则，请点击“保存规则”。

## 4. 批量修改交互次数

用表格软件打开 `ConfigSource/batch_interaction_updates.csv`。它只有两列：

| id | requiredInteractions |
| --- | --- |
| cube_sturdy | 4 |
| power_node | 2 |

每行填写一个已存在的交互物 ID 和新的次数，同一 ID 不要重复填写。保存后：

1. 打开 **批量更新** 页，点击 **预览批量更新**，检查修改前后的次数。
2. 确认无误后点击 **应用批量更新**，再确认写入。
3. 点击 **按草稿生成 JSON**，将修改输出给 Unity。

应用时会检查全部修改后的数据；有错误就不写 CSV。它会直接修改 `interactables.csv`，操作前应保留版本记录或备份。预览不会写文件。

## 5. 用 AI 编写规则（可选）

先试用 **AI 编写规则 → 离线演示：最小值改为 4**。点击“生成提案”，可体验预览、应用到草稿和校验流程。离线演示固定返回这一修改，不会理解其他需求。

在线使用可选 **DeepSeek** 或 **OpenAI**。需要对应服务的 API 密钥与可用额度。

在界面配置密钥：

1. 在 **AI 编写规则** 页选择 DeepSeek 或 OpenAI。
2. 将密钥粘贴到 **API 密钥** 框。输入会遮蔽显示，直接生成提案即可；默认仅本次运行使用。
3. 若希望下次自动加载，勾选 **在此电脑记住密钥**，再点击 **应用密钥设置**。密钥由 Windows 凭据管理器保存，不写进项目文件。

两种服务的密钥分别保存。点击 **忘记密钥** 可移除当前服务记住的密钥并清空输入；取消勾选后点击“应用密钥设置”，会移除已保存密钥，但保留本次输入。修改密钥后，只有再次应用设置才会更新保存的内容。

DeepSeek 默认模型为 `deepseek-flash`；OpenAI 需填写可用模型 ID。切换服务时，界面会分别保留本次输入的密钥与模型。请勿将密钥填入 CSV、规则文件或需求描述。

兼容环境变量配置：密钥框留空时，可使用 `DEEPSEEK_API_KEY` / `OPENAI_API_KEY`；模型可由 `DEEPSEEK_MODEL` / `OPENAI_MODEL` 预设。“忘记密钥”不会修改系统环境变量。非 Windows 平台支持本次输入，不提供记住密钥功能。

在线编写步骤：

1. 选择服务，填写密钥并检查模型名称。
2. 描述一项具体要求，例如：“把 requiredInteractions 的最小值改为 4，低于此值报错”。
3. 点击 **生成提案**，检查预览中的规则 ID、字段、数值和错误级别。差异中 `-` 表示旧内容，`+` 表示新内容。
4. 点击 **应用到草稿**。工具立即校验本地数据，请查看结果。
5. 需要保留这套规则时，再点击 **保存规则**。

AI 会接收你的需求、表头和当前规则，CSV 数据行不会发送。提案不会自动保存；结构错误的提案会被拒绝。等待提案期间如果修改了草稿，需要重新生成提案。

## 常见问题

| 提示或现象 | 处理方法 |
| --- | --- |
| CSV 列数不一致 | 检查多余逗号、缺失单元格或未配对引号，再保存 UTF-8 CSV |
| 找不到引用 | 检查 ID 拼写、目标表是否存在该 ID；场景引用问题请联系负责场景的同事 |
| 规则文件被其他程序修改 | 先记下要保留的草稿修改，再重新加载，避免覆盖他人的修改 |
| AI 提示缺少密钥 | 在当前服务的 API 密钥框中粘贴密钥 |
| 记住密钥失败 | 可先不勾选记住，直接使用本次输入的密钥 |
| AI 返回 HTTP 401 / 429 | 检查密钥或服务额度、限流情况 |
| AI 回复为空、被截断或提案无效 | 简化要求后重试；也可直接用规则表单编辑 |
| 无法写入文件 | 关闭占用 CSV 的表格软件，检查目录权限后重试 |

校验或 AI 检查未通过时，不会写入原文件。若发生磁盘写入故障或断电，请检查输出文件后重新生成。
